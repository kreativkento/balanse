h3. Who can write vs approve

* *Create / edit / delete:* admin, frontend (frontdesk), marketing, and dev
* *Everyone else:* read only
* {{admin_approved}} must be true before a post goes live
* *Admin* posts are approved automatically
* *Dev / frontend / marketing* posts start pending and wait in Staffing → Bulletin Approvals
* Only an *admin* can approve
* If a non-admin edits a live post, it goes back to pending
* Unapproved posts do not appear on public, member, or staff bulletin pages

h3. Post UID

Hidden Supabase UUID plus a short UID used in the UI.

*Format:* {{B-YYYYMMxxx}} (Philippines time). Resets to {{001}} each month. Example: {{B-202609001}}.

h3. Reach tags (visibility)

{{is_public}} is true only when visibility is public. A public post still needs admin approval before it goes live.

h3. Schedule and status

||Field||Meaning||
|Created|Set when the post is saved. Not editable|
|Post datetime|When the post goes live. A future value schedules it|
|Active until|When the post expires. Empty means it stays live until turned off|
|is_active|Stored true/false. Automatically set to false when active until is reached|

A post is *active* only when it is approved, {{is_active}} is true, post datetime has been reached, and active until is empty or still in the future. Public / member / staff pages show active posts only. Admin lists are split into *Active*, *Inactive*, and *Scheduled*. Writers can hold a post (turn it inactive) without deleting it.

h3. Post types

Event, Promo, Announcement, Update.

h3. Files

* Bucket: {{bulletin_resources}} (public read, writer upload)
* Optional preview image: {{image_path}} → {{post_id/cover/filename}}. Shown on list cards and the post detail modal
* Optional attachment: {{post_id/attachment/filename}} — images, PDF, Word. Limit 25 MB. Cover photo limit 10 MB
* If there is no cover photo, an image attachment is used as the card/detail preview
